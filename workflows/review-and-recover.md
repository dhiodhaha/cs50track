# Review the week and recover unfinished work

Status is accepted. The user approved the complete workflow package on 16 November 2026.

## Trigger

Prepare the review when the learner opens the app after a planned block ends, records a blocker, requests more time, or opens the weekly review. The review does not need a scheduled background run or an AI model.

Use Tuesday through Monday as a planning period because the accepted plan starts on Tuesday, 17 November 2026. Make the calendar dates visible so calendar weeks and course units cannot be confused.

## Brief

Show required groups passed, learning resources completed, active study time, missed or partially completed blocks, unresolved blockers, and the next period's planned course work. Keep the original 25 January target visible beside any proposed new target.

Count missing session time and unfinished work separately. A lecture or assignment completed ahead of time can release its remaining planned segments. A long study session does not imply a passing assignment. When a task uses its allocated time and remains unfinished, show Needs an estimate. Offer an editable two-hour additional block as a starting suggestion and label it an estimate. Do not present this as a measured prediction of the learner's pace.

## Proposal preparation

1. Read the latest accepted plan version, saved progress, and session records.
2. Identify unfinished segments and user-requested extra time. Remove segments whose work is complete. Keep their historical sessions and results.
3. Fill remaining Saturday catch-up capacity in course order, splitting work if necessary. Capacity is 150 minutes minus time already reserved by accepted catch-up segments. Do not place work on Sunday or the daily break.
4. If the next available Saturday cannot absorb the work before its dependent tasks, propose shifting later unfinished segments within the accepted study windows. Preserve task order, completed work, and historical logs.
5. If the ten-week calendar has insufficient capacity, extend it using the same availability pattern and calculate a proposed new target. Do not silently reduce the scope of required work.
6. Present added, moved, and removed segments, any target-date change, and the reason for the proposal. Link each item to the affected task.

Build one complete proposal before involving the learner. Saving a progress result must not require approving a schedule proposal.

## Checkpoint

Offer Apply plan, Keep current plan, and Edit estimate. Accepting applies the proposal atomically and stores the previous plan version. Keeping the current plan preserves the overdue work and accepted target. Editing an estimate prepares a new proposal.

The user explicitly required review of larger changes. Use the same Apply action for a simple Saturday catch-up suggestion so every accepted plan version has an explicit change record. Reapplying the same proposal has no further effect.

If availability or relevant progress changed after the proposal was created, recompute it before acceptance. Explain that the preview changed. Do not apply stale changes over newer records.

## Acceptance examples

- Missing a two-hour block can use an empty 2.5-hour Saturday block. The proposal leaves 30 minutes of reserve and keeps the target date.
- Missing four hours with an empty Saturday leaves 1.5 hours after its reserve is filled. Prepare any required later moves and show them for acceptance.
- Rejecting a proposal leaves the accepted timetable, target, and overdue work intact.
- A completed assignment's records remain intact after later blocks move.
- Reopening the app with no data changes produces the same proposed changes.
- Adding a two-hour session record does not by itself clear a failed assignment result.

## Plan status

Use On track when required work scheduled through the review date is complete and there is no unresolved deficit. Use Catch-up needed when the deficit fits before its dependencies in remaining reserved capacity. Use Plan review needed when it requires moving other work, an extra estimate, or a later target. Show the underlying missed work and available minutes next to the status.

The Progress view can plot cumulative required groups passed against the accepted plan's target dates. Plot real records and planned milestones separately. Label projections as planned. Do not interpolate an invented mastery or focus-quality score.
